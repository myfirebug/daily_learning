### POST 和 GET 的区别？

1. GET 在浏览器回退时是⽆害的，⽽ POST 会再次请求；
2. GET 产⽣的 URL 地址可以被收藏，⽽ POST 不可以；
3. GET 请求会被浏览器主动缓存，⽽ POST 不会，除⾮⼿动设置；
4. GET 请求只能进⾏ URL 编码，⽽ POST ⽀持多种编码⽅式；
5. GET 请求参数会被完整留存浏览器的历史记录⾥，⽽ POST 中的参数不会
   被保留；
6. GET 请求在 URL 中传送的参数是有⻓度限制的，⽽ POST 没有限制；
7. 对参数的数据类型，GET 只接受 ASCII 字符，⽽ POST 没有限制；
8. GET ⽐ POST 更不安全，因为参数直接暴露在 URL 上，所以不能⽤来传递
   敏感信息；
9. GET 参数通过 URL 传递，POST 放在 Request body 中；

### 什么是同源策略及限制?

同源策略限制从⼀个源加载的⽂档或脚本如何与来⾃另外⼀个源的资源进⾏交互。这
是⼀个⽤于隔离潜在恶意⽂件的关键的安全机制（协议、域名、端⼝号）

1. cookie、localstorage 和 indexDB ⽆法读取
2. DOM ⽆法获得
3. AJAX 请求不能发送

### 安全分类？

1. CSRF
   基本概念和缩写：通常称为跨站请求伪造，英⽂ cross-site request forgery 缩写 CSRF  
    **攻击原理**

   ⽤户登录过，某个接⼝存在漏洞，⾃动执⾏某个接⼝

   ⽤户 C 打开浏览器，访问受信任⽹站 A，输⼊⽤户名和密码请求登录⽹站
   A；

   在⽤户信息通过验证后，⽹站 A 产⽣ Cookie 信息并返回给浏览器，此时
   ⽤户登录⽹站 A 成功，可以正常发送请求到⽹站 A；

   ⽤户未退出⽹站 A 之前，在同⼀浏览器中，打开⼀个 TAB ⻚访问⽹站 B；
   ⽹站 B 接收到⽤户请求后，返回⼀些攻击性代码，并发出⼀个请求要求访
   问第三⽅站点 A；

   浏览器在接收到这些攻击性代码后，根据⽹站 B 的请求，在⽤户不知情的
   情况下携带 Cookie 信息，向⽹站 A 发出请求。⽹站 A 并不知道该请求其
   实是由 B 发起的，所以会根据⽤户 C 的 Cookie 信息以 C 的权限处理该请
   求，导致来⾃⽹站 B 的恶意代码被执⾏。

   **防御措施**
   Token 验证、Referer 验证、隐藏令牌

2. XSS
   基本概念和缩写：跨域脚本攻击，英⽂ cross-site scripting 缩写 XSS
   **攻击原理**

   不需要登录，向⻚⾯注⼊脚本运⾏

   **防御措施**

   让脚本不能执⾏
